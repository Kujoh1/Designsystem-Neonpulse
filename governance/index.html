01 · Das ProblemThe problem

Design-Drift: Qualität geht leise verloren.

Design drift: quality erodes quietly.

Ein Design System legt fest, wie das Produkt aussieht und sich anfühlt. Im Alltag weicht jede einzelne Änderung nur ein kleines bisschen ab – eine leicht andere Farbe hier, ein eigener Schatten dort. Einzeln fällt das niemandem auf. In Summe wirkt das Produkt nach einem Jahr wie aus fünf verschiedenen Häusern.

A design system defines how the product looks and feels. Day to day, each change drifts only a little — a slightly different colour here, a custom shadow there. Nobody notices one at a time. After a year, the product looks like it came from five different companies.

03 · So funktioniert'sHow it works

Vier Schritte. Einer davon menschlich.

Four steps. One of them human.

Der Guardian sitzt dort, wo Änderungen ohnehin besprochen werden: im Änderungsvorschlag auf GitHub (dem „Pull Request“). Niemand muss ein neues Tool lernen.

The Guardian sits where changes are discussed anyway: in the change request on GitHub (the “pull request”). Nobody has to learn a new tool.

  1. 01

    Änderung einreichen

    Submit a change

    Ein Teammitglied schlägt eine Änderung am Produkt vor – wie bisher.

    A team member proposes a change to the product — as they do today.

  2. 02

    Automatische Prüfung

    Automatic review

    Der Guardian liest nur die geänderten Stellen und vergleicht sie mit dem Regelwerk des Design Systems.

    The Guardian reads only the changed lines and compares them with the design system's rulebook.

  3. 03

    Konkretes Feedback

    Concrete feedback

    Er schreibt einen Kommentar: was abweicht, wie schwer es wiegt und welche Korrektur passt.

    It posts a comment: what deviates, how serious it is and which fix applies.

  4. 04

    Mensch gibt frei

    A person approves

    Das Team korrigiert, eine verantwortliche Person gibt frei. Erst dann geht es live.

    The team fixes, an accountable person approves. Only then does it go live.

Das Regelwerk ist das Herzstück. Es beschreibt Farben, Schriften, Abstände, Prinzipien und Tonalität in Klartext, liegt versioniert neben dem Code und wird vom Design-Team gepflegt. Eine neue Regel ist eine Textänderung – kein Software-Projekt.

The rulebook is the core. It describes colours, type, spacing, principles and tone in plain language, is versioned next to the code and owned by the design team. A new rule is a text edit — not a software project.

06 · NutzenValue

Was das Unternehmen davon hat.

What the business gets.

Konsistenz

Consistency

Derselbe Maßstab für jede Änderung, jedes Team und jede Zeitzone – das Produkt wirkt wie aus einem Guss.

The same standard for every change, team and time zone — the product feels like one piece.

Tempo

Speed

Feedback direkt nach dem Einreichen statt Warten auf den nächsten Review-Termin.

Feedback right after submission instead of waiting for the next review slot.

Skalierung

Scale

Design-Qualität wächst mit der Zahl der Teams, ohne dass jede Prüfung durch das Design-Team laufen muss.

Design quality grows with the number of teams, without every review going through the design team.

Entlastung

Focus

Designer:innen arbeiten an Produktfragen, nicht an der Kontrolle von Farbcodes und Abständen.

Designers work on product questions, not on policing colour codes and spacing.

Lerneffekt

Learning

Jeder Fund erklärt das Warum. Neue Kolleg:innen lernen das System nebenbei – das verkürzt das Onboarding.

Every finding explains the why. New colleagues learn the system along the way — shorter onboarding.

Transparenz

Transparency

Jede Prüfung ist in der Änderung dokumentiert und nachvollziehbar – auch Monate später.

Every review is documented on the change and traceable — even months later.
